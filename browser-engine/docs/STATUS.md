# 실사용 목표와 검증 상태 — 2026-10-09

목표: 자체 엔진을 유지하며 메모리 사용을 줄이고, 높은 보안과 주요 웹사이트 호환성을 갖춘 Windows 브라우저를 만든다.
버전 번호는 구현 단계를 표시하며 완성도 백분율을 의미하지 않는다.

## 현재 구현과 한계

| 항목 | 상태 | 확인 내용 / 남은 조건 |
| --- | --- | --- |
| 자체 HTML/DOM/기초 CSS/레이아웃 | 구현 | Chromium/WebView 미사용. 일반 사이트의 CSS 범위는 미완성 |
| 분리 렌더러와 제한된 IPC | 구현 | 문자열·링크 전체 예산, 이미지·글자 크기 검증 |
| Windows 권한 제한 | 구현 | Restricted Token + Low Integrity + Job. AppContainer 미구현 |
| 반응형 로딩·취소 | 구현 | 한 작업자, 유한 큐, 취소된 세대·다른 탭 결과 폐기 |
| 탭·주소 검색·북마크 | 구현 | 탭 16개, 이력 256개/탭, 북마크 128개 |
| 한글 출력·문자 입력 | 구현 | 로컬 글꼴 지연 처리. Windows IME 실기기 조합 검증 필요 |
| HTTPS 연결·인증서 검사 | 구현 | rustls 루트 인증서 검증 유지. 네트워크 호환성 테스트 확대 필요 |
| JavaScript·DOM 이벤트·폼·로그인 | 미구현 | 주요 사이트 이용을 위한 핵심 과제 |
| Flex/Grid·선택·미디어·다운로드 | 미구현 | 실사용을 위해 필요 |
| OS 강제 네트워크·파일 격리 | 미완성 | AppContainer 또는 동등 경계와 실패 시 차단 검증 필요 |
| 배포·업데이트 | 일부 | portable EXE 생성. 코드 서명·설치·업데이트 필요 |
| 크롬·엣지 비교 | 미실시 | 같은 사이트·탭·기능을 갖춘 상태로 측정해야 함 |

## 이번 작업에서 수행한 검증

- Rust 양쪽 바이너리의 자동 테스트: 48개 통과.
- Linux에서 분리 렌더러 문서 처리, 한글 유지, script 텍스트 미표시 smoke test 통과.
- 막힌 렌더러를 취소 신호로 종료하는 watchdog smoke test 통과.
- 한글 읽기 HTML을 PPM으로 렌더링하고 글자·링크·줄 배치를 눈으로 확인.
- 가상 X11 화면에서 16개 탭 열기·전환·닫기, 주소 편집과 차단, 내장 북마크 화면 조작 확인.
- Windows GNU 타깃 타입/컴파일 검사 수행. Windows native CI가 MSVC release 빌드와 권한 제한 smoke test를 다시 수행한다.

### 메모리 측정 범위

Linux debug 실행, Xvfb, NanumGothic 글꼴, 내장 시작 페이지를 사용한 **브로커 RSS**를 측정했다.
글꼴을 모든 글자 단위로 미리 풀어두던 구현은 약 90 MiB였고, 지연 처리로 바꾼 후 약 14 MiB 수준이었다.
탭 수 증가에는 페이지 재그리기·할당자 워밍업 비용도 포함되며, 실제 외부 사이트의 메모리 측정이 아니다.
이 결과에 Windows·렌더러·웹사이트·크롬·엣지와의 비교 의미를 부여하면 안 된다.

## 일상용 완료 판정에 필요한 작업

1. 네트워크 호환성: HTTP 압축·인코딩·쿠키·연결 재사용과 인증서 오류/리디렉션 통합 테스트.
2. 문서 호환성: HTML 파싱 규칙, CSS 선택자/레이아웃, Unicode shaping와 폼·선택·포커스.
3. 스크립트: 격리된 JavaScript 런타임, DOM/Web API, 이벤트·타이머·비동기 작업, 보안 정책.
4. 운영체제 격리: 렌더러 파일/네트워크 접근을 실제 OS가 거부하는 테스트.
5. 실사용 시나리오: 네이버·Google·메일·YouTube 등에서 검색·로그인·입력·파일·미디어 검증.
6. 배포·비교: Windows IME/클립보드·장시간 실행·복구·서명·업데이트, 동등 조건의 메모리/CPU 비교.

현재 결과는 이 목표에 도달하기 위한 구현이며, 목표 전체가 달성됐다고 보고하지 않는다.
