# 단둘이 데이트 코스 2.0 — 데이터 기반 (1단계)

## 현재 적용 범위

- 새 `couples/{coupleId}/datePlans/{planId}` 컬렉션은 미완성 상태도 저장하는 **공동 초안**입니다. `status: draft`, `schemaVersion: 2`만 허용합니다.
- 새 `.../candidates/{candidateId}` 하위 컬렉션은 **그 데이트만을 위한 장소 후보**입니다. 이름, 주소, 좌표, 분류, 메모와 생성자 정보를 독립적으로 저장합니다. 전체 `datePlaces` 보관함에는 자동 저장하지 않습니다.
- 이미 전체 보관함에 저장된 장소를 가져온 경우 `sourceSavedPlaceId`는 선택적인 참조입니다. 장소의 기본 정보는 후보 문서에 따로 보관해 보관함과 독립적으로 취급합니다.
- `dateCourses` 및 `datePlaces`의 기존 경로·쓰기 API·화면은 변경하지 않습니다. 기존 코스는 `readLegacyDateCourse`로 **읽기 전용 호환 뷰**를 만들 수 있습니다. 기존 데이터를 자동 이관·삭제하지 않습니다.
- `datePlanDrafts.ts`의 새 API는 추후 UI 연결용으로만 추가했습니다. 1단계에서는 사용자 화면을 교체하거나 기존 코스 저장 방식을 변경하지 않습니다.

## 후속 단계 계약

- 2단계: PC 지도/모바일 전환과 후보 등록. 동일 후보 등록 방지를 검색/좌표 기준으로 처리.
- 3단계: 후보별 개인 선호(`want / considering / pass`), 댓글, 시간대별 주 방문·예비 후보. 독립 문서로 보관하여 동시 수정을 분리.
- 4단계: `DatePlanTimeBlock` 형식의 반자동 시간표. 화면에서는 **시/분**으로 입력하고 저장은 분 단위 정수로 처리. 고정 시간 충돌은 별도 검사.
- 5단계: 최종 확정본의 불변 버전과 별도 변경 제안, 두 사람의 승인, 동시 수정 충돌 검사. **현재 규칙은 draft만 허용하므로 확정 상태를 임의로 기록할 수 없습니다.**
- 기존 코스를 2.0으로 변환하는 별도 작업에서는 장소 ID/순서/시간을 보존하고 사용자 확인을 받습니다.

## 보안/배포

커플 두 사람만 계획과 후보를 읽고 변경할 수 있습니다. 생성자/생성 시각/문서 식별자/상태는 이후 임의 변경 불가합니다. 미완성 초안에 제목·날짜·후보가 없어도 저장할 수 있습니다. 모든 신규 API는 명시적으로 호출할 때만 실행됩니다.
