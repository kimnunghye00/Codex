# 단둘이 발자취·데이트 지도 — P0 전환 계획

상태: 구현 준비 단계. 이 문서는 마이그레이션을 **실행하지 않는다**.

## 현재 구조 확인 (2026-09-19, main)

- `src/utils/location.ts`: 사용자 UID별 `meluni-location-visits:<uid>` 로컬 캐시. `LocationVisit`은 GPS 이동 지점과 도착·출발 시각을 담으며 실제 체류 판정이나 커플의 공동 방문 증명은 아님. 오래된 방문 기록은 최대 300개까지만 로컬 로드/저장.
- `src/lib/locationRealtime.ts`: 기존 `couples/{coupleId}/locations/{ownerUid}-{visitId}`에 공유된 방문 위치 저장. 날짜별로 파트너 기록 구독.
- `src/components/location/LocationPage.tsx`: 지도는 내 위치 공유 및 상대방 날짜별 발자취. 'footprints' 탭은 새 공동 추억 모델이 아님.
- `src/home-map-overlay.ts`: 홈 지도는 현재 내 로컬 방문 기록을 지도 호스트에 전달. 클릭을 캡처하는 전역 이벤트 처리도 있으므로 홈 진입 동선을 바꿀 때 함께 수정해야 함.
- `src/types.ts`, `src/lib/coupleMemories.ts`: 기존 사진·영상은 `Memory` 및 `couples/{coupleId}/memories`에 존재. 추억의 `location`은 자유 입력 텍스트이며 장소 ID나 좌표가 아님.
- `src/components/home/CoupleHomeTools.tsx` 및 `src/components/memories/MemoriesPage.tsx`: 일정·데이트 계획은 기존 일정 문서와 로컬 `route-date-plans:<uid>`를 사용. 앞으로 별도의 코스 ID로 연결해야 함.
- `firestore.rules`: 기존 위치 및 추억 컬렉션에만 현재 권한 모델이 있음. 새 개인·공동 발자취 컬렉션의 규칙은 아직 없음.

## 이번 P0 코드

`src/lib/footprintFoundation.ts`는 기존 `LocationVisit`을 **읽기 전용 개인 미검토 미리보기**로 변환한다. 유효하지 않은 좌표·시간·중복 ID를 걸러내며, 이전 위치 기록을 자동으로 공동 발자취나 '방문 확정'으로 표시하지 않는다. 동일 장소명·같은 한국 날짜의 앨범 기록은 **연결 제안**만 생성한다. 이미지는 복제하거나 업로드하지 않는다. 호출부에서 실제 사용자의 UID로 범위를 제한해야 한다.

## 다음 단계에서 반드시 먼저 구현할 사항

1. 비공개 GPS 원본 및 개인 방문 후보의 사용자별 접근 제어. 기존 공유 `locations`에 자동 기록을 저장하지 말 것. 새 모델의 Firestore Security Rules 및 에뮬레이터 테스트부터 작성.
2. 계획 장소·코스·실제 방문·GPS 경로를 각각 구별하는 저장 스키마와 안정적인 ID. 재방문은 다른 방문 ID를 사용하되 장소 ID는 재사용.
3. 개인 방문 후보는 상대방이 확인하기 전 공유 발자취에 노출 금지. 기존 공유 기록을 자동 승인한 기록으로 이관하지 말 것.
4. 공동 발자취의 수정은 제안 문서를 통해 상대방 승인 후 반영. 요청자가 스스로 승인하는 변조를 서버 규칙에서 차단.
5. 기존 사진은 `memoryId` 링크만 저장. 명칭/날짜가 비슷하다는 이유만으로 자동 연결하지 말 것.
6. 사용자별 자동 기록 설정은 기본 꺼짐. 기존의 '위치 공유' 토글과 새 백그라운드 수집 동의를 동일한 설정으로 간주하지 말 것.
7. 홈 왼쪽 지도만 발자취로 교체. 오른쪽 카드 구성·모바일 D+ 가독성은 유지. 지도 탭은 미래 데이트 계획으로 전환하고 앨범에서 발자취 상세 진입.
8. Android 실제 기기 위치 권한·일시정지·앱 종료·배터리·정확도 확인. 웹에서는 장시간 백그라운드 GPS 수집을 보장하지 않음.
9. 영상의 외부 공유용 경로는 집·직장 등 민감 위치와 해당 구간·장소명·사진 메타데이터 제거 결과를 검토하도록 할 것.

## 배포 주의

이 브랜치는 기존 앱의 실시간 화면·Firestore 데이터를 **변경하지 않음**. 테스트와 코드 리뷰 전에는 `main` 병합 및 배포하지 않는다. 기존 데이터 마이그레이션은 백업과 롤백, 실행 전 샘플 검증을 갖춘 별도 작업으로 진행.
