# 단둘이 Firebase 권한·두 계정 흐름 검증

검증 기준: `043c37ffaa807749ac6c7d31f825cb76fa2c98c3`에서 시작한 수정본, 2026-09-14.

## 실행과 범위

- `npm ci`
- `npm run test:security` — Node 22.13 이상, Java 17 이상 필요.
- `npm run stability` — 타입 검사, 웹 빌드, 기존 런타임·정적·번들 검사.
- 테스트는 고정된 `demo-danduli-security` 프로젝트의 Auth/Firestore/Storage 에뮬레이터만 사용한다. 운영 계정이나 운영 데이터를 생성·변경하지 않는다.
- DB/Storage 싱글턴만 테스트 클라이언트로 교체한다. 프로필 저장·초대 생성/요청/수락·메시지 전송·반응·삭제·첨부 업로드·연결 해제는 실제 앱 서비스 함수를 호출한다.
- 전화번호 인증은 Auth Emulator의 모의 SMS 코드와 Firebase Auth 자격 증명을 사용한다. 실제 SMS 배송, reCAPTCHA, Android WebView/IME, 화면 클릭·사진 렌더링, 카메라 이미지 압축은 이 테스트의 검증 범위가 아니다.

## 해결한 문제

1. 구성원 변경을 전부 금지하던 규칙과 연결 해제 트랜잭션의 충돌을 해결했다. 구성원 삭제와 본인 연결 정보 삭제가 함께 일어나는 해제만 허용한다. 구성원 교체·탈퇴 후 복구·외부 접근은 거절한다.
2. 커플 생성은 만료되지 않은 초대 요청, 소유자의 수락, 정확한 두 구성원, 본인 연결 포인터를 원자적으로 검증한다. 가입자가 선택한 초대 예약을 함께 저장해 동시 초대와 가입자의 완료 전 중복 연결도 막는다.
3. 사용자가 임의로 다른 커플의 ID를 자기 프로필에 써서 권한을 얻지 못하도록 한다. 기존 커플 기록은 유지하되, 검증된 초대가 없는 과거 기록으로 비동의자의 프로필을 읽는 경로는 허용하지 않는다.
4. 메시지 작성자·본문·서버 저장 시각의 변조를 차단한다. 전체 삭제는 본인 메시지이고 서버 저장 시각부터 10분 미만인 경우만 허용한다. 오래된 메시지는 나에게만 숨길 수 있다.
5. 반응·숨김 변경은 본인 상태만 변경한다. 반응 설정 함수는 상대 반응을 보존한다. 이전 이미지 최적화 작업은 작성자 본인의 메시지만 변경한다.
6. 연결 해제로 권한을 잃은 구독은 연결 없음 상태를 알린다. 앱의 기존 커플 메시지·추억 캐시와 화면 상태를 정리하며, 서버 기록에 삭제 표시를 만들지 않는다. 상대방의 오래된 연결 포인터 때문에 다음 연결이 막히지 않도록 한다.
7. 첨부 파일의 실제 MIME을 전송하고 Storage의 동영상 파일 유형을 명시적으로 지원한다. 상대 파일 덮어쓰기·삭제, 외부 계정 읽기·쓰기, 미지원 MIME 업로드는 거절한다.
8. 정상 통화 종료 시 수신자도 발신자 명의의 통화 기록을 남길 수 있도록 제한된 예외를 유지한다. 임의의 상대 명의 텍스트/다른 통화 기록은 허용하지 않는다.

## 결과와 한계

- 기존 Firestore 규칙을 같은 테스트에 로드하면 12개 시나리오 중 9개가 실패한다. 시나리오 실패 수는 독립적인 취약점 수와 동일하지 않다.
- 수정된 규칙은 12개 시나리오 전체 통과. `npm run stability`의 웹 빌드·런타임 6개·정적·번들 검사도 통과했다. 이후 변경에는 PR/CI 결과를 다시 확인한다.
- 정상 흐름은 두 전화번호 계정 → 프로필 → 상호 연결 → 양방향 메시지 → PNG 첨부 및 GIF 이미지 업로드/다운로드 → 실시간 연결 해제 감지 → 양쪽 인증 SDK의 기존 자료 접근 거절을 검증한다.
- 기존 다운로드 토큰 URL의 철회, 이미 다운로드한 사본, 오프라인 네이티브 캐시의 원격 삭제는 보장하지 않는다. 전체 출시 승인이나 실기기 E2E 테스트 완료를 의미하지 않는다.

## 배포

- Stability Gate와 웹 배포 workflow에 에뮬레이터 검증을 추가했다.
- 웹 배포는 Firestore/Storage 규칙 배포에 성공한 다음 Hosting을 배포한다. 배포는 원자적이지 않으므로 Hosting 실패 시 재실행이 필요하다.
- 배포 계정에 Firestore/Storage 규칙 배포 권한이 없으면 배포가 실패한다. Hosting만 우회 배포해서는 안 된다.
- 새 연결 프로토콜은 `inviteCode`와 `pendingInviteCode`를 사용한다. 새 커플 연결에는 업데이트된 클라이언트가 필요하다. 이미 연결된 커플은 새 필드가 없어도 기존 자료 접근과 연결 해제가 가능하다.
- 설치된 APK는 웹 배포만으로 업데이트되지 않는다. Android 배포본 업데이트와 실제 휴대폰 두 대의 SMS/화면/통화 확인이 별도로 필요하다.
